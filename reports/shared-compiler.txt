Shared compiler rewrite (2026-10-17)

Scope
The complete PR uses the ordinary Fusor tensor/compiler path.
There is no ExecutionProfile, gpu_inference constructor, Apple adapter preset,
model-specific schedule pin, or alternate Llama decode implementation.
The only model-source change is adopting the shared immutable GGUF byte storage
interface; graph construction, sampling, and device selection match main.

Compiler changes
- Recognize normalization from Map/Fold/View algebra. Retain the logical graph
  for differentiation and price the fused launch during normal extraction.
- Recognize single-query attention from QK, stable softmax, and PV contractions,
  including grouped heads and prefix masks. Width comes from the operands;
  fixed subgroup width and resource limits determine legality. Unsupported
  cases retain the existing algebraic implementation.
- Coalesced Q4/Q6 loads are selected from format, layout and subgroup legality.
  Whole-block storage views preserve buffer bytes and checked accesses.
- Forward affine views and pure map slabs through the ordinary compiler.
- Lower contiguous range updates into ordinary WebGPU copy/clear commands.
- Keep symbolic single-index scatter geometry in uniforms; growth changes the
  dispatch grid without compiling another shader.
- Keep full-size and expanding views in the producer's replay plan. Only partial views
  materialize their base separately, avoiding stale reshaped intermediates.

Runtime changes
- Generic QMatrix and dense-layer GGUF loaders share immutable host bytes,
  as does the model loader. Concatenation retains segments without copying
  every weight into another full host allocation.
- Bounded prepared-plan/artifact caches apply to normal resolves.
- One compiler worker by default avoids retaining a cohort of lowered kernels.
- Submission overlaps preparation within the existing in-flight resource bound.
- Production replay keeps its incumbent by default. Explicit online tuning is
  still available, but no longer substitutes an alternative every 16 resolves.
- Cache-only donation and its alias-specific lowering have been removed.
  Ordinary scatter preserves its input and retained views. Prepared GPU
  artifacts share the normal plan's weak ownership; no alternate plan is needed.

Validation
- Core compiler/runtime cargo check passed (fusor, fusor-gpu, fusor-ir,
  fusor-cost, libraries/tests, kernel-observer feature).
- Two compiler construction tests passed: ordinary normalization across four
  shapes with absent/16/32/64-wide subgroups, and ordinary attention across
  five channel widths, grouped heads, concrete and symbolic key extents.
  Unsupported CPU/no-subgroup attention and incorrect normalization decline.
- Five ordinary-device WebGPU tests passed in 17.90 seconds: RMS/attention
  vs host results, zero-shader copy lowering, concrete and symbolic full-size
  view replay, scatter input/retained-view preservation, and Q4/Q6 results
  against dequantized references at N=1024/1027, K=4096, one/three input rows.
  The aligned cases observe both coalesced lowerings without a preset; odd
  dimensions may select another legal schedule and still match every value.
- Symbolic grouped attention crosses 256 keys, grows storage to 512 slots,
  and remains correct through 260 keys with zero extra shader compilations.
- All 29 visualizer Rust tests and 14 Python tool tests pass.
- Formatting and diff whitespace checks pass. CI formatting also passed.

Resource validation
Checks used one compiler job and one GPU process, at least 12 GiB starting
memory headroom, a 1 GiB process-group RSS cap, no additional swapouts, a 32 MiB
compressor-growth ceiling, and a 1 GiB runtime disk reserve. Small incremental
tests may start with that disk reserve plus a 64 MiB linking allowance; larger
checks require 1.5 GiB at startup. No model was loaded for these checks.
The final GPU suite peaked at 0.500 GiB process-group RSS, with at least
16.174 GiB memory headroom and no added swapouts.

An expanded fixture initially exceeded its process-group cap while retaining
multiple matrix graphs. It now releases the graph, device and GPU pool between
cases and completes inside the same cap. When another workload reduced free
disk below the reserve, builds were refused. They resumed after space recovered;
only obsolete task-owned executables and check metadata were removed.

Follow-up verification
The complete Fusor workspace/all-target Clippy check passed locally, including
CPU/GPU backends and kernel-observer examples. CI Clippy, formatting, macOS
build, and WebGPU build also passed after the stale test helpers and new lint
warnings were corrected. The matrix diagnostic now recognizes transfer records.

A further expanding-broadcast regression caught a stale second replay: expanding
views must stay with their producer, just like full-size views. The size proof
now preserves that behavior for constant and matching symbolic factors. This
case is included in both the explicit GPU fixture and the ordinary session unit
tests (CI selects WebGPU). Its final local rerun and model/example compatibility
check were refused after system headroom fell below 12 GiB and free disk then
fell below the 1 GiB reserve. They remain pending; the earlier five-test GPU
pass predates this additional broadcast case. CI is being rerun on the fix. Its Clippy job now explicitly enables the
kernel-observer examples and checks both model visualization/profiling examples,
so optional tooling is covered on future changes as well.

Historical measurements
All reports under llama-decode-2x and llama-8x describe earlier experimental
checkpoints. In particular, the October 12 2.020x result used a preset which is
now removed. It is not a throughput claim for this compiler rewrite.
The previously built release chat executable also predates this rewrite.
